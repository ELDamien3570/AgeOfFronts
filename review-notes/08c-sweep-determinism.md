## How it works today

**Where determinism matters.** One `Skirmish` per match runs inside `serverMatchWorker.ts`; browsers never simulate. Commands reach the worker as an ordered `advance` batch (`LiveMatch.ts:735-744` → `serverMatchWorker.ts:251-265`), are applied through `CommandApplications.apply` (receipt dedupe by `${playerId}:${id}`), then `match.step()` runs exactly `ticks = 1` (`LiveMatch.ts:718`). Clock debt is paid by scheduling more frequent single-tick requests, never by multi-tick batches. Consequently cross-client divergence is impossible; determinism matters only for (a) the ~60 checkpoint-continuation tests, (b) `DiagnosticReplay` fixtures restored into the browser worker (`worker.ts:113-116`), (c) command-arrival fairness (first-received wins, inherent), and (d) any future crash recovery / host migration.

**Randomness.** `Simulation.ts:784` seeds sfc32 (`src/core/PseudoRandom.ts`, 32-bit integer ops, platform independent) from `options.seed` (`LiveMatch.ts:150`, `Math.random()`). The stream is consumed only at construction (starting positions, deposits, `FactionRoster` with its own per-kind streams at `FactionRoster.ts:20-27`, map generation). No runtime code draws from `this.random` (only lines 241/335/447/784 reference it). Runtime "randomness" is stateless hashing: `RangedAim.ts:6-11` (splitmix of a caller-supplied seed), `Trade.ts:199` raid sampling seeded from `tick/owner`. So the checkpointed `random` state is effectively inert after setup, and no AI or combat decision depends on draw order.

**Checkpoint tree.** `Skirmish.checkpoint()` (`Simulation.ts:241`) returns `structuredClone` of: options, players, squads/buildings/ships (EntityCollection values), volleys, defenseZones, owners/claims/progress (Uint8Array), detours, navigationProgress, orderRevisions, queuedLegs, moveContinuations, routeApproaches, controlGenerations, activeClaims, tick/winner/combatTicks/producedTroops/nextId/nextVolleyId, random, forest, routeWork, routePlanner (`planning`), movementAdmission, shipAdmission, commandApplications, recruitment, expansion, territoryAbsorption, coastalTerritory, homeTerritory, wasteland, avoidance, attackApproaches, passageTraffic, conquest, playerAttacks. `Expansion.checkpoint()` (`Expansion.ts:146`) nests trenches, skirmish stance, features, progression, diplomacy, fortifications, supply, trade (→ receiving), roads, battle, armies (→ cohorts), engagements, modernization, economy (→ routes, tradeQuotes, coasts, ledger, assets, losses, recovery, cities, defenses, fronts, modernFronts, navalFacts → sequences, naval, military → armyPlanner → invasion, boundaries, placements), aircraft, winners, events, nextEvent, tribePlans, geography, operations, relations. Every class exporting `checkpoint()` is reachable from this tree except `CrowdRecovery` (saved by `LocalAvoidance` but deliberately not restored, see Issues) and `FormationPlanning`/`IncrementalPath`, which are serialised as plain state inside MovementAdmission/CohortAdmission/RoutePlanner jobs.

**Restore.** `Simulation.restore` (`Simulation.ts:242-287`) validates shape/identity/recipes/clocks, then `installCheckpoint` (`289-343`) clones the input, restores entity collections (which rebuild `UnitIndex` buckets ordered by a canonical ordinal, `UnitIndex.ts:50-63`), rebuilds owned-tile maps, adjacency, spatial grids from the canonical arrays (`342`), re-bases navigation `policyWait` revisions (`340`), and sets a `restoreFailure` latch if a sub-restore throws so a half-restored world can never step (`205-209, 283-287`). Caches not in the checkpoint are all derived and either cleared in `restore` (capture*, movementClearance, columnCertificates, pressure) or keyed by revisions/ticks that the restore invalidates (`squadChanges.invalidate()`, `tileChanges.invalidate()`, `navigationCleanupNeeded`, `landingSpatial=undefined`, `routeClassificationEpoch` only feeds a WeakMap cache that is re-created). Path warming (`pathsWarm/warmGraph`, `Simulation.ts:592-593, 3393-3398`) restarts after restore, but `HierarchicalPaths.warm` only pre-builds trees that are otherwise built lazily (`HierarchicalPaths.ts:454-462`) and corridor eligibility is gated on `tick >= corridorTicks` which is map-derived (`Simulation.ts:797-799, 816`), so results are identical and only tick time differs.

**Serialisation.** `StateCodec.encodeState` (`StateCodec.ts:343-385`) packs Maps/Sets with insertion order, typed arrays (RLE for map-sized byte arrays), preserves `-0`, rejects non-finite numbers, gzips and SHA-256 hashes; `StateDelta` reproduces key order exactly (`StateDelta.ts:6-8`). `HostedRuntime`/`CommitVerifier` (per-tick checkpoint + delta commit) are referenced only by themselves and tests — the live server never checkpoints. Production checkpoint consumers today: none. Tooling consumers: tests, `DiagnosticReplay` (version 11, map "migration" only).

**Versioning.** Checkpoint `version: 11` (`Simulation.ts:241, 250, 290`; `DiagnosticReplay.ts:26`). `FORMATION_RULES_VERSION = 12` (`Manpower.ts:5`) is written into presentation packets and checked by the decoder (`SnapshotCodec.ts:377, 479`) — it never touches checkpoints. `CONTENT_HASH` (`Catalog.ts:96`, FNV over canonicalised content incl. `combatRevision`, doctrines, defences) is written into snapshots (`Expansion.ts:1893`) but compared nowhere except the client Unit Lab draft cache (`client/lab/UnitLab.ts:110`). Sub-objects with real versioning: `RoutePlanner` scheduling versions 1-4 (`RoutePlanner.ts:141, 183-186, 234`), `TacticalFeatureIndex` (`sourceHash` + `navigationRulesVersion: 2`, `TacticalFeatureIndex.ts:73-100`), `PlanningWorkspace` capacity check.

**Numeric model.** Squad `x/y` are integers: per-tick velocities are `Math.round`ed (`FormationLocomotion.ts:164, 218-222`; `LocalAvoidance.ts:219-220, 306, 445-448`). Health is integer subunits (`HEALTH_SCALE = 1000`, `damageManpower` floors applied damage, `Manpower.ts:97-125`). Reserves are integers with a 0..999 `reserveRemainder` (validated at `Simulation.ts:277`). Gold is integer: per-second income at `produceReserves` (`tick % TICKS_PER_SECOND`), trade payouts floored (`TradeQuote.ts:45-49`), deposit yields integer × integer multiplier (`Supply.ts:371`, `Economy.ts:7`). Per-second cadences use `tick % secondsToTicks(n)` (no raw `tick % <literal>` remains). Floats that *do* persist across ticks in authoritative state: `Squad.locomotion.{speed,heading,targetHeading}` (sin/cos/atan2/hypot/sqrt), ship `x/y` (`moveShip` adds `dx/dy` without rounding), projectile aim points (`RangedAim.ts:48-52`, log/cos/sin), `Trade.lostValue/capturedValue` (stats). All are deterministic on a single V8 build.

## Strengths

- Runtime randomness is hash-based, not stream-based; the PRNG is only used during setup. Decision order cannot depend on how many draws other systems made.
- Every authoritative sort comparator (223 reviewed) is tie-broken by id/tile/key or operates on canonical-ordered input; V8's stable sort then makes ties order-independent. Example of good practice: `Battle.ts:1157` sorts incoming warheads by impact, blast, id; interception site choice at `1170` is min(impactTick, building.id), so the `Set` iteration order at `1163` is irrelevant.
- Integer-first numeric design where it matters: tile ownership bytes, integer squad positions, subunit health, remainder-based reserves, floored gold. Float drift is confined to locomotion/aim, where positions are re-quantised each tick.
- Checkpoint discipline is unusually thorough: 60+ sub-objects with explicit `checkpoint()/restore()`, derived indexes rebuilt rather than serialised, careful "don't alias the saved object" cloning, `-0`/non-finite handling in the codec, validation-before-install plus a poison latch, and ~10 control-vs-resumed equality tests (all four I ran pass on the working tree).
- `Object.keys` over `Record<number, …>` (progression, inventories, jobs, priorities) iterates ascending-numerically by spec, so insertion order can never leak into behaviour there.
- The 8 Hz migration converted constants via `TICKS_PER_SECOND` / `secondsToTicks` rather than by hand-editing numbers (`git show a0d02507`); no `% 20`, `* 20`, `=== 20` tick remnants remain in `src/skirmish`.

## Issues

Severity: H/M/L. Confidence: CONFIRMED = traced end to end; SUSPECT = plausible from code read, not executed.

### I1. Missile defence constants were never rescaled to 8 Hz — M, CONFIRMED
- `src/skirmish/content/MissileDefense.ts:3` `MISSILE_DEFENSE_RELOAD_TICKS = 400` and `:4` `MISSILE_DEFENSE_SPEED = 4 * FIXED` (per tick). Consumed at `src/skirmish/domain/Battle.ts:1175` (`nextAttackTick: tick + MISSILE_DEFENSE_RELOAD_TICKS`) and `src/skirmish/domain/MissileInterception.ts:44` (`interval(vv - MISSILE_DEFENSE_SPEED ** 2, b, qq)`).
- Mechanism: `git log` shows the file last changed in 185be868 and it is absent from the 8hz commit's 181-file list. At 20 Hz these meant a 20 s reload and 80 tiles/s interceptor; at 8 Hz they mean a 50 s reload and 32 tiles/s. Meanwhile the threats *were* rescaled: `ModernWeapons.ts:13` strategic flight `speed: 3600 / TICKS_PER_SECOND` (180 → 450 units/tick), `:33` and `:44` projectile speeds `/ TICKS_PER_SECOND`.
- Consequence: interceptor/missile speed ratio fell from 5.7× to 2.3×, each launcher fires 2.5× less often, and `interceptionPoint`'s tick-granular `delay = Math.ceil(...)` has fewer ticks to work with. Late-age nuclear/MIRV balance silently shifted toward the attacker. `CONTENT_HASH` includes these (`Catalog.ts:119`) but nothing checks it.
- Repro: `interceptionPoint(p, tick, x, y, r)` with a strategic projectile at 8 Hz vs the same world at `TICKS_PER_SECOND = 20`: compare `delay`/null outcomes; and `SimulationTiming.test.ts` "preserves … rates in seconds" does not cover `MISSILE_DEFENSE_*`.

### I2. Checkpoints carry no rules/content/tick-rate fingerprint — M (tooling) / L (prod), CONFIRMED
- `src/skirmish/Simulation.ts:241` writes only `version: 11`; `:250` and `:290` compare version, map size, `JSON.stringify(options)` and presence of `expansion`. `DiagnosticReplay.ts:26` likewise. `CONTENT_HASH` (`Catalog.ts:96`) is never compared on the server; `FORMATION_RULES_VERSION` (`Manpower.ts:5`) only guards presentation packets (`SnapshotCodec.ts:479`).
- Mechanism: a checkpoint taken by a build with different unit/recipe/defence content or at 20 Hz has identical shape. Restore-time validation (`Simulation.ts:265`, `validateRecipeManpower`) catches changed `soldierHp`/capacity only. Timer fields (`remainingTicks`, `nextAttackTick`, `deadline`, `retryAt`, `nextThink`, `expiresTick`) and content-derived values are accepted verbatim.
- Consequence: fixtures captured before the 8 Hz switch (or before the pending balance revision) restore "successfully" into a world where every saved countdown is 2.5× longer and AI budgets/leases are mis-priced; continuation tests would compare apples to apples and pass, hiding the mismatch. Not a production hazard today because production never restores.

### I3. `LocalAvoidance` saves CrowdRecovery state but restores it empty, and the subsystem is dead — L, CONFIRMED
- `src/skirmish/LocalAvoidance.ts:116` serialises `recovery: this.recovery.checkpoint()`; `:126` calls `this.recovery.restore()` with no argument (comment: "Historical friendly yield leases no longer constrain the overlap policy"). `grep this.recovery.` in the file finds only those two lines; `CrowdRecovery.frame` (`CrowdRecovery.ts:37`) has no runtime caller.
- Consequence: today harmless (nothing reads the leases), but the checkpoint carries data that cannot round-trip, and if `frame()` is re-wired, control vs resumed matches will diverge silently. Also `AiRecovery.ts:243` serialises `known` that `:251` rebuilds from buildings and never reads — harmless redundancy that bloats checkpoints at the 430-building scale.

### I4. Autonomous-planning options are feature flags encoded as literal tick counts, and production does not set them — M, CONFIRMED (effect on prod config) / SUSPECT (intent)
- `src/skirmish/Protocol.ts` `autonomousRouteDeadlineTicks?: 16` / `autonomousDecisionInterval?: 12` (literal types, changed from `40`/`30` in the 8hz diff); `Simulation.ts:746-748` rejects any other value; `:799, 815, 3394, 4998` use `=== secondsToTicks(2)` as the feature gate.
- `LiveMatch.ts:143-163` builds production options from `DEFAULT_AI_POLICIES` (`AiPolicies.ts:3-9`: aiEconomy/deferredPlanning/aiDefenses/aiNaval/aiWarPolicy) + `FORMATION_MOVEMENT` — neither sets the two autonomous options; `serverMatchWorker.ts:138-145` only adds `territoryIncomeScale`. Tests that assert 8 Hz scheduling set them explicitly (`tests/skirmish/AiDecisionScheduling.test.ts:9`, `ShipMovementAdmission.test.ts:19`, `TradeFleet.test.ts:33`).
- Consequence: in production the 2 s autonomous route deadline, the amphibious corridor warming (`corridorTicks.amphibious = Infinity` at `:799`) and the 1.5 s AI decision cadence are OFF, while the continuation tests exercise them ON. Either the ARM qualification numbers were taken with a different config than tests validate, or the feature is intentionally test-only; either way a future tick-rate change will break the `=== secondsToTicks(2)` gates (a `16 as const` option literally cannot be written for 10 Hz).

### I5. No seed/command journal, so production incidents are not reproducible — M, CONFIRMED
- Seed: `LiveMatch.ts:150` `Math.floor(Math.random() * 0x7fffffff)`; the `match-runtime-diagnostics` log at `serverMatchWorker.ts:297` does not include options/seed. Commands are consumed from `this.commands.splice(0)` (`LiveMatch.ts:735`) and never persisted with their tick. `DiagnosticReplay` (`DiagnosticReplay.ts:3-9`) needs a full checkpoint and only accepts `mapId: "migration"`.
- Consequence: the freeze class from 2026-10-15 can only be reproduced if someone captured a checkpoint in the browser worker; the authoritative server state that actually froze is gone. Given the sim is deterministic from (map, seed, options, [tick, command]…), a journal would make every freeze replayable offline.

### I6. Production has no checkpoint at all; the entire restore machinery is test-only — M (design), CONFIRMED
- `serverMatchWorker.ts:115-310` never calls `match.checkpoint()`; `HostedRuntime`/`CommitVerifier` (which do, per tick) are only referenced by each other and tests. Crash of a `ReservedMatchWorker` loses the match (known).
- Consequence: all of the checkpoint completeness work protects tests and the browser diagnostic path, not players. The cost of adding periodic checkpoints is the `structuredClone` + pack + gzip + SHA-256 of a 52-faction world (CommitVerifier comment: "a full-map baseline costs about a second to encode on the largest maps") on the single sim thread.

### I7. Math.ceil rounding at 8 Hz lengthened several sub-second timings by 25-150 % — L, CONFIRMED
- `content/ModernWeapons.ts:19` `reloadTicks: secondsToTicks(0.05)` → 1 tick = 125 ms (was 1 tick = 50 ms at 20 Hz; WeaponTiming's `shotsPerReload` path keeps RPM, per `SimulationTiming.test.ts` "600 RPM").
- `content/Units.ts:137` `undefendedCaptureTicks: secondsToTicks(0.2)` → 2 ticks = 250 ms (was 4 = 200 ms); `:391` `runupTicks: secondsToTicks(0.3)` → 3 ticks = 375 ms (was 6 = 300 ms).
- `domain/ChargeImpact.ts:46` `duration: secondsToTicks(1.2)` → 10 ticks = 1.25 s; `disruption: secondsToTicks(.4)` → 4 ticks = 0.5 s (was 8 = 0.4 s).
- `domain/AiDefenseDirector.ts:531`, `domain/AiEconomicDirector.ts:227` `tick % secondsToTicks(.15)` → every 2 ticks (250 ms) vs every 3 (150 ms).
- `Rules.ts:267` `ARCHER_ARROW_TICKS = secondsToTicks(0.6)` → 5 ticks = 625 ms.
- Consequence: small, mostly in favour of defenders/charges; worth a conscious re-tune rather than an accident of `Math.ceil`.

### I8. Cross-host float reproducibility of restored checkpoints depends on the V8 version — L, SUSPECT
- 123 `Math.sin`, 118 `Math.cos`, 58 `Math.atan2`, 125 `Math.hypot`, 77 `Math.sqrt`, 6 `Math.exp`, 2 `Math.pow`, 2 `Math.log` in `src/skirmish` (excl. client). Persisted float state: `Squad.locomotion` (`FormationLocomotion.ts:57-61, 218-219`), ship `x/y` (`Simulation.ts` moveShip `setOwned(ship.id, "x", ship.x + dx)`, no rounding), aim points (`RangedAim.ts:48-52`).
- `Math.sqrt` is IEEE-correctly-rounded everywhere; V8 implements sin/cos/exp/log/pow/atan2 in its own software `ieee754` port (no hardware FMA), so x64 vs ARM on the *same* V8 are bit-identical; different V8 majors are not guaranteed. A `DiagnosticReplay` fixture captured under Node 20/x64 and replayed on Node 22/ARM (or vice versa) can diverge in heading/aim after a few ticks. Not a production concern (single process).

### I9. `localeCompare(…, "en")` tie-breaks and content hashing are ICU-dependent — L, SUSPECT
- `domain/Battle.ts:512` (kill-credit tie-break on `"squad:12"`-style keys), `domain/Combat.ts:242-246`, `domain/AiMilitaryDevelopment.ts:104`, `content/Catalog.ts:83` (CONTENT_HASH key order). Since CONTENT_HASH is only used by the Unit Lab and the sim runs on one host, impact today is nil; it becomes real if I2/I5 are implemented and the hash crosses hosts.

## Recommendations (prioritised)

1. **Rescale missile defence (I1) — ~1 h.** `MISSILE_DEFENSE_RELOAD_TICKS = secondsToTicks(20)`, `MISSILE_DEFENSE_SPEED = 80 * FIXED / TICKS_PER_SECOND`; extend `SimulationTiming.test.ts` "preserves … rates in seconds" with both. Then re-check `interceptionPoint` at 8 Hz: with `delay = Math.ceil(...)` in ticks the earliest intercept is ≥ 125 ms out, so consider `missileDefenseRange` +1 tile at low stack to restore the 20 Hz coverage. Trade-off: moves balance back toward defenders; a deliberate nerf should be expressed in seconds, not left to tick rounding.
2. **Fingerprint checkpoints (I2) — ~2 h.** Add `rules: { version: 11, ticksPerSecond: TICKS_PER_SECOND, contentHash: CONTENT_HASH, formationRules: FORMATION_RULES_VERSION, scheduling: 4 }` to `Skirmish.checkpoint()`; reject mismatches in `restore` and `readDiagnosticReplay`. Keep `version` for structural changes only. Trade-off: every stored fixture becomes invalid on any content edit; mitigate with an explicit `allowContentMismatch` flag for the Unit Lab/balance tooling only.
3. **Match journal (I5, I10) — ~1 day.** At `prepare`/`start`, log `{event:"match-start", matchId, mapHash, seed, options}`; in the worker append `(tick, playerId, command, disconnectedPlayerIds)` per advance to a bounded per-match file/ring (commands are already Zod-validated and small). Add `replayJournal(map, options, journal)` to `DiagnosticReplay` (drop the `mapId: "migration"` restriction). Trade-off: a few KB/min of disk per match; must redact player names if logs are shared.
4. **Periodic server checkpoint for crash recovery (I6) — ~3-5 days.** Every 60 s (or on quiet ticks) `encodeState(match.checkpoint())` to disk; on worker death `Master` respawns the worker with the last checkpoint and clients re-sync via the existing `client-baseline` path (`serverMatchWorker.ts:210-214`). Cost at target scale ≈ 0.3-1 s stall per checkpoint; mitigate by packing in the worker (synchronous `structuredClone` + `pack`) and gzip/hash in a sibling thread via transferable buffers. Requires (2) first so a redeploy never restores a stale-content checkpoint.
5. **Make autonomous planning a boolean option (I4) — ~2 h.** Replace `autonomousRouteDeadlineTicks?: 16` / `autonomousDecisionInterval?: 12` with `autonomousRouteDeadline?: boolean` / `autonomousDecisions?: boolean` and derive ticks via `secondsToTicks(2)` / `secondsToTicks(1.5)` at construction; decide explicitly whether production enables them (add to `DEFAULT_AI_POLICIES` if yes) and re-run the ARM qualification with the production config. Trade-off: breaks fixtures that carry the literal (they are already rejected by `Simulation.ts:746-748` if stale).
6. **Tick-rate lint test — ~1 h.** A test that scans `src/skirmish/content/**` and `Rules.ts` for identifiers ending in `TICKS`/`Ticks`/`speed`/`reload` whose initialiser lacks `TICKS_PER_SECOND`/`secondsToTicks`, allow-listed explicitly. Would have caught I1. Also add `**/out/**` to both vitest excludes (I12).
7. **Re-tune the ceil-rounded timings in seconds (I7) — ~1 h.** Either accept and document (e.g. `runupTicks: secondsToTicks(0.375)`) or switch the few sub-second ones to `Math.round`-based conversion where a ±62 ms error is preferable to a systematic +25 %.
8. **Trim dead checkpoint state (I3) — ~30 min.** Delete `CrowdRecovery` from `LocalAvoidance` (or re-wire and restore it), and drop `known` from `AiRecovery.checkpoint()`.
9. **Optional float hygiene (I8) — ~1 h.** Round ship `x/y` per tick like squads so all positions are integers; pin the Node major in production and in the replay tooling, and record `process.versions.v8` in the journal header so a divergent replay is explainable.

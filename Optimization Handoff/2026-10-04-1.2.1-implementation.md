## Performance evidence and limits

`tests/skirmish/optimizationBenchmark.ts` loads the exact original journal, Trade and CanonicalStateStream sources via `git show`, using guarded temporary sibling files and finally removing them. It runs locally with `node --import tsx tests/skirmish/optimizationBenchmark.ts`. Do not run build/runtime-hash capture concurrently while those temporary files exist. The report records runtime identity, candidate source hashes, environment, operation counts and all 60 alternating paired samples after eight warmups. Dependencies are the current candidate modules for both original and new Trade code, isolating that algorithm rather than claiming a frozen complete-runtime comparison.

Measured environment: Windows x64, Node 24.18.0, Ryzen 7 3700X, 16 logical CPUs, approximately 51.4 GB RAM. This is not the two-core ARM target.

Representative p95 from `local-benchmarks.json`:

| Fixture | Original | Candidate | Scope |
| --- | ---: | ---: | --- |
| Near-cap land trade: 54 factions, 2,592 actors | 25.49 ms | 1.64 ms | One fixed-tick pass; empty goods, no productive deliveries, no active naval interception. |
| Barrier transfer projection: 1,000 barriers, 256,000 geometry tiles | 40.49 ms | 0.25 ms | Worker-side projection construction only; downstream postMessage still copies for recipients. |
| Four spatial contracts, 10,000 unchanged squads | 3.17 ms | 0.04 ms | Warm reuse; no movement/membership invalidation. |
| Same spatial workload after position invalidation | 3.07 ms | 3.09 ms | Rebuild cost approximately unchanged; all-moving worlds remain O(total rows). |

Journal fixtures cover 32,768 retained IDs and 100 reads per sample: quiet reads visit zero records, a single changed-ID read visits one, rather than scanning retained history. The report also includes zero, 236 and 1,296 trader fixtures. Zero-fleet overhead does not establish a universal win; read the raw distributions.

Capture experiment history is explicit. `rejected-capture-cache.json` records the initial radius-2 prototype, which is **not the production radius**. `tests/skirmish/captureExperiment.ts` repeats a bounded fixed-radius prototype using the actual `CAPTURE_RADIUS` (3); `capture-radius3-experiment.json` records approximately 0.33 ms versus 0.35 ms mean and 0.51 ms versus 0.97 ms p99 for 1,000 stationary centers. Even warm-cache evidence does not justify integration; moving misses and invalidation were not measured. The production radius iteration remains the original path.

These are deterministic/reference tests and synthetic microbenchmarks. They demonstrate algorithm-specific gains, **not** whole-match speedup, target-count gameplay capacity, active-human participation, publication latency, ARM qualification or rendered FPS. No Oracle access is needed to reproduce them.

### Full-source local continuation

`tests/skirmish/optimizationReplay.ts` compares the complete frozen original `src` tree (created with `git archive 6409654 src`) against the candidate in separate processes. Order is baseline, candidate, candidate, baseline. Both restore the same existing Old World 1000 checkpoint at tick 60,000 and run 1,200 ticks with all recorded AI options enabled, no rule overrides, and snapshot extraction every four ticks. Timing arrays are bounded to the declared run length; the local stop condition is 180 seconds per trial. Map factories come from each trial's own source tree to preserve class/forest identity.

Input population is 37 factions (10 AI, 25 tribes, two idle human seats), 492 squads, five ships, 619 buildings and 25 traders. Map dimensions are 1000 x 750. Checkpoint provenance includes an earlier diagnostic transport-candidate filtering experiment; this replay applies no such filtering. This fixture is useful for regression comparison and is not target-count or organic long-soak acceptance. Its ignored input remains at `out/overnight-1000/seed42-filtered/checkpoint-60000.v8`; each report records its SHA-256, options and source fingerprint.
